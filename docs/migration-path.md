# 迁移路径

第一版以 Markdown 为中心。这是刻意选择。

Markdown 易读、易编辑、易 diff，也容易由模型生成。但它不一定是未来所有场景的最终存储层。

## 可能的演进

```text
Markdown 文件
  -> 带验证器的 Markdown
  -> 索引化知识存储
  -> 图数据库
  -> 协作服务
```

## 必须保持稳定的东西

- ID
- 类型
- schema 版本
- 证据引用
- 关系语义
- 状态生命周期
- 变更历史

## 可以变化的东西

- 存储后端
- 检索策略
- UI
- 评审流程
- 评估自动化
- 图谱可视化

## 设计规则

在知识方法被证明有效之前，不要过早优化存储后端。
